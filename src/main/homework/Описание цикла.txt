**Обнаружение циклической зависимости**

На первом этапе зависимости между сервисами внедрялись через @Autowired на полях (Field Injection).
В процессе реализации возникла циклическая зависимость между ClientService и AccountService:
- ClientService использовал AccountService для получения списка аккаунтов (счетов) клиента через метод getAccountsByClientId().
- AccountService использовал ClientService для получения клиента при открытии нового счёта через метод getClientEntity().
Таким образом, сервисы не только ссылались друг на друга через внедрённые зависимости, но и непосредственно вызывали методы друг друга для выполнения своих операций.

При запуске приложения Spring начинал создавать AccountController, которому требовался AccountService.
Для создания AccountService был необходим ClientService, а для создания ClientService снова требовался AccountService.
Получалась следующая цепочка: AccountController → AccountService → ClientService → AccountService.

При использовании Field Injection приложение удалось запустить после установки свойства spring.main.allow-circular-references=true,
разрешающего Spring работать с циклическими зависимостями.
Затем Field Injection был заменён на Constructor Injection при сохранении прежней структуры зависимостей.
В результате приложение завершилось с ошибкой BeanCurrentlyInCreationException (в логах она отображалась через UnsatisfiedDependencyException).

Причина заключается в том, что при Constructor Injection для создания каждого сервиса уже необходим готовый экземпляр другого сервиса.
Spring не может завершить создание ни одного из двух бинов, поскольку каждый ожидает второй.

**Устранение циклической зависимости**

Для решения проблемы сервисы были переработаны таким образом, чтобы они больше не зависели друг от друга напрямую:
- ClientService больше не зависит от AccountService и AccountRepository.
  Для получения клиента вместе с его счетами используется ClientRepository с методом findWithAccountsById(),
  использующим @EntityGraph. Это позволяет загрузить клиента и связанные с ним счета одним SQL-запросом.
- AccountService получил прямую зависимость от ClientRepository и самостоятельно проверяет существование клиента при открытии аккаунта.

В результате взаимная зависимость сервисов была устранена; приложение успешно запускается.
